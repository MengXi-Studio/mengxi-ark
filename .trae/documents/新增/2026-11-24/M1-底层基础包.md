# M1 底层基础包（utils / theme / hooks）实施方案

> 任务文档遵循 `workflow.md` 文档驱动四步流程。当前状态：**已完成（实施记录已回填）**。
> 依据：`渐进式中台前端框架实施方案.md` M1「@mengxi-ark/utils、@mengxi-ark/theme、@mengxi-ark/hooks 完成，配套单元测试、基础文档」。

## 需求

完成三个底层包的实际实现（M0 只建了壳）：

1. `@mengxi-ark/utils`：纯函数层（数据格式化 / 数据结构 / 浏览器工具 / 校验与编码）
2. `@mengxi-ark/theme`：Design Token（基础层 + 语义层 + dark + UI 库桥接）
3. `@mengxi-ark/hooks`：六个通用 hooks（useRequest / useAuth / useSession / useI18n / useTable / useForm）
4. 配套单元测试与基础文档

## 需求分析

**涉及包与文件：**

| 包    | 落点                               | 关键约束                                                               |
| ----- | ---------------------------------- | ---------------------------------------------------------------------- |
| utils | `packages/utils/src/<分类>/`       | 单一文件单一分类；零依赖、无 Vue、无副作用；Web/Node 双端兼容          |
| theme | `packages/theme/src/`              | 只含 SCSS；基础层→语义层两级；`--mx-*` 前缀；dark.scss 必须同步；无 JS |
| hooks | `packages/hooks/src/useXxx/`       | 仅依赖 Vue/Pinia/VueRouter；不劫持路由；请求实例业务注入；卸载自动清理 |
| 测试  | 各包 `__tests__/` + 根 vitest 配置 | hooks 需 DOM 环境（jsdom/happy-dom）；utils 纯 Node 环境               |
| demo  | `apps/demo-light/`（最小壳）       | hooks 运行验证载体（DoD 第 4 项）                                      |
| 文档  | `apps/docs/`（VitePress 壳）       | 快速上手板块，禁提 runtime                                             |

**依赖边界：** utils(0) / theme(0) / hooks(1) 均在依赖链底层，hooks 不 import utils/theme？——**是**，方案 §2 中 hooks 与 theme/utils 平级向下，hooks 不依赖它们（hooks 只依赖 Vue 生态）；demo-light 可 import 全部三包。

**影响面：** 各包 package.json（exports 按新入口扩展）、vitest 工作区配置、turbo test 管道、demo-light 新建、docs 壳新建。

## 伪代码设计

### utils 导出清单（按建议范围，待 Q1 确认）

```
src/
├── format/        # formatDate(ts, pattern) / formatMoney(n, {precision, symbol}) / formatNumber / formatDict
├── tree/          # forEachTree / mapTree / findTree / filterTree（treeConfig 支持 children 字段名）
├── object/        # deepClone / merge / omit / pick
├── array/         # unique / groupBy / chunk
├── browser/       # download(blob|string, filename) / exportCsv / getUrlParam
├── validate/      # isPhone / isEmail / isIdCard / isEmpty
└── index.ts       # 汇总导出（Tree-Shaking 友好，re-export 各分类）
```

### theme token 结构（按 §7 契约，待 Q2 确认色值）

```
src/
├── tokens/
│   ├── _color.scss      # 色板变量（$mx-palette-*）→ :root 输出基础色板 + 语义功能色
│   ├── _spacing.scss    # --mx-spacing-{xs..xl}
│   ├── _radius.scss     # --mx-radius-{sm,base,lg,round}
│   ├── _shadow.scss     # --mx-shadow-{sm,base,lg}
│   └── _z-index.scss    # --mx-z-{base,sticky,dropdown,drawer,modal,message}
├── _semantic.scss       # 语义层：--mx-color-text-* / bg-* / border-* 引用基础层
├── base.scss            # reset / 排版 / 空状态 / loading
├── dark.scss            # [data-theme="dark"] 覆盖语义层
├── adapters/{antdv.scss, element-plus.scss}
└── index.scss           # @use 汇总
```

### hooks 目录结构（全部六个，待 Q3/Q4 确认范围）

```
src/
├── useRequest/
│   ├── index.ts         # 签名: useRequest(source, options?) → { data, loading, error, run, cancel, refresh, retry }
│   └── __tests__/
├── useAuth/             # hasPermission(code|code[], mode?) + v-permission 指令导出
├── useSession/          # token 存取介质可配（localStorage/cookie），onSessionExpired 回调
├── useI18n/             # messages 注册 + locale 响应式 + t()
├── useTable/            # { dataSource, loading, pagination, search, reset }
└── useForm/             # 数据层：setFieldsValue / reset / validate（Form 实例耦合待 Q4）
```

关键实现分支：

- useRequest 竞态保护：请求序号递增，响应回写前比对序号，旧响应丢弃。
- useAuth 降级链：传入 adapter → inject 探测 → 安全默认 false + warn 一次。
- useSession：`onSessionExpired` 只回调，不跳路由。

## 实施记录

### 方案落地形态（与伪代码设计的差异说明）

1. **theme 文件命名**：落地为无下划线形式（`tokens/color.scss`），与规范 §7.1 目录契约一致（伪代码草稿中的 `_color.scss` 前缀废弃）。
2. **theme 分层细化**：功能色（success/warning/danger/info）与语义色 CSS 变量放 `semantic.scss`，供 `dark.scss` 覆盖（满足 §7.2.4 暗色同步）；基础色板（primary 梯度 / 灰阶）主题间不变，dark 禁止重定义。
3. **utils deepClone 实现**：JSON 兜底路径改为「序列化前递归把 Date 预处理为标记对象 + parse 时 reviver 还原」——实测 Node 22 下 `JSON.stringify` 的 replacer 收到的 Date 已是 `toJSON`
   转换后的字符串，无法拦截；语义与方案一致。
4. **hooks 契约内小幅补充**：`useAuth` 增加导出 `setAuthAdapter()`（`v-permission` 运行于渲染周期外无法 inject，需模块级权限源）；`useTable` 返回值增加 `error`；`useRequest.retry()` 为手动重试上次请求，自动重试由
   `options.retry` 配置。
5. **@vue/test-utils 锁 2.4.6**：latest 2.6.0 依赖链（js-beautify → nopt@10）要求 Node ≥24.15.0，本机 24.14.0 且 engine-strict=true，Node 升级后可再放版本。
6. **theme 引入方式**：theme 包 exports 契约为 `"." → ./dist/index.css`，子路径 `@mengxi-ark/theme/dist/index.css` 未导出；demo 与文档统一用 `import '@mengxi-ark/theme'`，文档加注说明。
7. **跨包工程收口（M1 过程中暴露的仓库级问题，已修）**：
   - `internal/eslint-config`：`ignores` 中 `dist/**` 为根相对模式，未排除嵌套包 dist，改为 `**/dist/**`；新增 `__tests__` 关闭 `vue/one-component-per-file`（测试文件内联多组件属合理场景）。
   - 7 个包 package.json 存在 UTF-8 BOM 导致 `check-peer-deps.mjs` JSON.parse 失败：已剥离现有 BOM，并在脚本读取层 `.replace(/^\uFEFF/, '')` 根治。
   - `turbo.json` build outputs 增加 `.vitepress/dist/**`（docs 产物路径）。
   - `packages/utils/tsconfig.json` 补 `exclude: ["src/**/__tests__/**"]`（与 hooks 对齐，消除 dist 中 spec 声明文件泄漏）。
