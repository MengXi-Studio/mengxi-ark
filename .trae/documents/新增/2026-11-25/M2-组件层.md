# M2 组件层（components / biz-components 双模式）实施方案

> 依据：`渐进式中台前端框架实施方案.md` §3.4 / §3.5 / M2；工程规范 §6（组件库规范）；M2 定义「components 通用增强组件 + biz-components 首期 Lov、单据Table 双模式 + demo-light 示例」。

## 需求

1. `@mengxi-ark/components`：通用增强组件（方案 §3.4 清单：SearchForm 高级查询区、增强 Table、TreeSelect、Upload、Dialog、Drawer、统一空状态、异常兜底、状态标签、Result 结果页）
2. `@mengxi-ark/biz-components`：首期 **Lov 值集选择器、单据 Table**，实现双模式核心能力（独立模式 props 自请求 / 基座联动 inject 探测）
3. demo-light 扩充组件演示；docs 文档双示例（独立模式 + 基座联动）

## 需求分析

**依赖边界（自 M1 后已可用）：**

- components(2) 可 import hooks(1)（useRequest / useTable / useAuth）与 theme(0)（CSS Variables）——合法。
- biz-components(3) 可 import components / hooks / theme；仅经 `inject(MX_RUNTIME_CONTEXT_KEY)` 探测基座，禁止 import runtime。
- UI 库（ant-design-vue / element-plus）只允许出现在各包 `adapter/` 目录（规范 §6.3），组件文件通过 `inject(UI_ADAPTER_KEY)` 取适配器，默认适配器 Ant Design Vue。

**新增工程问题：** components / biz-components 从「空壳」变为真实组件包，涉及 UI 库依赖形式、SFC 构建产物（CSS 抽离按需导入）、适配器双库实现等，M1 未覆盖，见疑问清单。

**影响面：** packages/components、packages/biz-components 全量实现；两者 package.json（新增 peer、exports 扩展）；demo-light 增演示面板；docs 增两包文档页（各含独立/基座双示例）；changesets 登记。

## 伪代码设计

### 适配器接口（components/src/adapter/，biz-components 复用 components 的适配器）

```
adapter/
├── types.ts          # UiAdapter 接口：input/select/button/dialog/drawer/table/form/upload/treeSelect 等原子能力映射 + token 常量
├── key.ts            # UI_ADAPTER_KEY 注入常量
├── antdv.ts          # Ant Design Vue 实现（映射 a-input/a-select/... → 统一 props）
└── element-plus.ts   # Element Plus 实现（规范 §6.3：两套必须同步落地）
```

### components 组件目录（五件套契约 §6.1：index.ts / Xxx.vue / types.ts / style/index.scss / __tests__）

按方案 §3.4 全清单（范围待 Q1 分批）：

```
SearchForm/    # 查询区：fields 配置（input/select/dateRange...）+ 折叠展开 + 查询/重置事件
EnhanceTable/  # 增强 Table：columns 配置、工具栏插槽、状态标签列、空状态统一
EmptyState/ StatusTag/ ResultPage/   # 轻量展示件（仅 token 样式，不依赖 UI 库）
Dialog/ Drawer/ Upload/ TreeSelect/  # 适配器封装薄壳
```

### biz-components 双模式装配（adapter.ts 上下文探测与 props 兜底）

```
Lov/
├── index.ts / Lov.vue / types.ts / style/index.scss / __tests__/
└── adapter.ts   # resolveContext(): inject(MX_RUNTIME_CONTEXT_KEY) 探测
                 #   命中字段 → 复用（lovListApi / 值集缓存 / 权限）
                 #   缺失 → 回退同名 props（lovApi / params / ...）→ 都无 → 独立模式
DocumentTable/   # 单据 Table：基于 EnhanceTable + 行编辑态 + 校验 + 保存事件 emit（不自带提交）
```

关键分支（Lov 为例）：
- 独立模式：`useRequest(lovApi, { immediate: params 变化防抖触发 })` 自请求；
- 基座联动：探测到上下文 lovListApi / 值集缓存则复用，缓存 key 同值集编码；
- 上下文丢失运行时降级不抛异常。

### 构建与样式

- 沿用 defineLibConfig（Vite lib mode），SFC 编译 + CSS 抽离；`exports` 增加 `"./style"` 或子路径样式入口（M1 遗留 TODO 1，此时落地）。
- 组件样式只引用 `var(--mx-*)`，随包产出独立 css。

- 使用者装了哪个 UI 库就消费哪套适配器实现，未装时轻量展示件（EmptyState 等，不依赖 UI 库）仍可用；
- theme 的 `adapters/*.scss` 桥接变量已就位。
是否认可？还是接受「组件包强依赖 antdv」（体积大但实现简单）？

## 实施决策补充（实现前定稿）

1. **适配器「统一契约」形态**：adapter 不只映射组件引用，而是把各 UI 库组件包装为**统一 props/事件外壳**——统一 `modelValue` + `update:modelValue`、`size: sm|md|lg`（antdv→small/middle/large，EP→small/default/large）、Select 统一 `options: {label,value,disabled?}[]`、DataTable 统一 `columns/dataSource/rowKey/pagination/rowSelection` + `bodyCell({column,record,index})` 槽 + `pageChange/sortChange/rowClick` 事件 + `empty` 槽、Modal 统一 `open/update:open/ok/cancel`、TreeNode 统一 `{key,title,children}`。
2. **默认适配器动态解析**：adapter/antdv.ts 内用 `defineAsyncComponent(() => import('ant-design-vue').then(...))` 包外壳——antdv/element-plus 均不出现在顶层 import（保持 optional peer 语义，未安装 UI 库时 EmptyState/StatusTag/ResultPage 等纯展示件可独立使用）；`inject(UI_ADAPTER_KEY)` 未命中时回退缓存单例 `createAntdvAdapter()`。
3. **MX_RUNTIME_CONTEXT_KEY 落点**：`biz-components/src/context/`（key.ts + types.ts + resolve.ts），biz-components 导出；M3 runtime 反向 import biz-components 取同一 key（合法方向）。上下文字段首期：`user/tenant/org/permissions/lovListApi/lovCache`；props 兜底映射：`lovListApi↔lovApi`、`lovCache↔lovCache`。
4. **Lov 两形态**：静态值集模式（context.lovCache / props.lovCache[lovCode] / props.lovOptions 命中 → adapter Select 直选）；远程接口模式（context.lovListApi 或 props.lovApi → 弹窗 DataTable + 条件搜索（keyword 约定字段）+ 分页（currentPage/pageSize）+ params 防抖 300ms；lovApi 返回数组=不分页、{list,total}=分页）。解析优先级：context → props → 独立空态（warn 一次不抛异常）。
5. **DocumentTable 校验**：本地轻量 rules（required/message/validator）实现，不走 useForm（useForm 依赖适配器表单实例，行级编辑场景不适用；差异将在实施记录注明）。
6. **defineLibConfig 扩展**：新增 `externals?: (string|RegExp)[]` 与 `cssFileName?: string` 选项；components/biz-components 构建外部化 `ant-design-vue`/`element-plus`（动态 import 原样保留），CSS 抽离为 `dist/index.css`，package.json exports 增加 `"./style.css"`。
7. **类型检查**：两包 typecheck 脚本改用 `vue-tsc --noEmit -p tsconfig.spec.json`（SFC 类型可查）；新增 devDeps：sass / vue-tsc / happy-dom / @vue/test-utils。
8. **demo-light**：新增依赖 @mengxi-ark/components、@mengxi-ark/biz-components、ant-design-vue ^4；main.ts 引入 `ant-design-vue/dist/reset.css`；App.vue 增「组件」页签；Lov 双模式用条件包裹 `BaseMockProvider`（provide mock 上下文）验证降级切换。
9. **组件命名**：与 UI 库易混淆的壳组件用 Mx 前缀：MxDialog/MxDrawer/MxUpload/MxTreeSelect；其余按方案名 SearchForm/EnhanceTable/EmptyState/StatusTag/ResultPage。

## 实施记录

### 方案落地形态（与伪代码设计的差异）

1. **适配器统一契约扩展**：实际实现比伪代码多收敛了两类差异——DataTable 增加 `rowDblclick` 事件（DocumentTable 双击进入编辑依赖）与 Upload 统一 `MxUploadItem`（antdv 语义 status：'uploading' | 'done' | 'error'），EP 侧在适配器内做 status/uid 双向映射（`mapEpUploadFiles` / `normalizeEpUploadItems`，均纯函数可单测）。
2. **DocumentTable 校验未走 useForm（按决策 5 执行）**：行级编辑是「多实例、无统一表单实例、逐单元格触发」场景，useForm 的「单表单实例 + 整体 validate」模型不适配；落地为本地轻量 rules（`validateCell` / `validateRows` 纯函数），错误结构为 `rowKey → dataIndex → message`。
3. **dts 构建踩坑（新增经验，已记入 LESSONS_LEARNED）**：vite-plugin-dts（unplugin-dts 1.1.2）的 Vue processor 自动探测在本工程 `include: ['src']` 形式下不生效，SFC 的 `.d.ts` 不产出导致 dist 内 `./Xxx.vue` 引用悬空（下游 TS2307）；defineLibConfig 显式配置 `processor: 'vue'` + `cleanVueFileName: true` 后修复（`./Xxx.vue` 引用自动重写为 `./Xxx`）。
4. **适配器 h() 类型策略**：antdv/EP 惰性组件显式标注为宽松 `Component`（props 按 any 渲染）。原因：统一契约外壳的 props 类型与各 UI 库组件类型不逐字段重合，保留强类型会让 `h()` 双向推断产生大量误报；适配器边界是类型收敛点，运行时行为不变。
5. **单测的 props 驱动模拟**：Lov / DocumentTable 为 v-model 契约，单测通过拦截 `update:modelValue` 回写 props（setProps / reactive splice）模拟宿主绑定，保证 props 驱动语义被真实验证。
