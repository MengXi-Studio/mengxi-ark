# 梦曦工作室 · 渐进式中台前端框架实施方案

> 组织：梦曦工作室 MengXi-Studio
> 组织地址：<https://github.com/orgs/MengXi-Studio/repositories>
> 项目代号：**MengXi Ark（曦舟）**
> 仓库地址：`[https://github.com/MengXi-Studio/mengxi-ark](https://github.com/MengXi-Studio/mengxi-ark)`
> 开源协议：MIT（宽松友好，适合企业商用、二次开发）
> 定位：**渐进式中台前端框架，基座可选、组件可独立、业务组件双模式，介于 Vben-Admin 与 HZERO-C7N 之间**
> 核心口号：轻量可开箱，中台可插拔；不强制绑定，可渐进升级

> 核心设计原则回顾
>
> 1. 单向依赖，禁止反向/循环依赖
> 2. Runtime、DSL 渲染引擎为**可选包**，不是强制依赖
> 3. 业务组件双模式：独立模式 / 基座联动模式
> 4. 手写SFC为一等公民，配置渲染仅为加速方案
> 5. 全量TypeScript，契约优先，语义化版本管理

## 1. 技术选型与整体架构

### 基础技术栈

* 运行框架：Vue3（Composition API）
* 构建工具：Vite + esbuild
* 语言：TypeScript 5.x，严格模式 `strict: true`
* 状态管理：Pinia 4（ESM-only）
* 路由：Vue Router 5
* 包管理：pnpm
* Monorepo：Turborepo
* 样式：SCSS + CSS Variables（Design Token）
* 测试：Vitest（单元测试）、Playwright（E2E）
* 代码规范：ESLint + Prettier + simple-git-hooks
* 文档：VitePress
* 打包产物：ES Module 为主，支持 CJS；完整类型声明 `.d.ts`

### UI 适配层设计（解耦底层UI库）

内置适配适配器，首期优先支持：`Ant Design Vue`、`Element Plus`；后续可扩展 Naive UI。

> 框架内核、hooks、业务组件不直接耦合单一UI库，通过适配器隔离差异。

### 依赖流向（单向，自上而下）

```
@mengxi-ark/cli
    ↓
应用层（业务项目 / 业务模块包）
    ↓
【可选】@mengxi-ark/runtime
【可选】@mengxi-ark/dsl-render
    ↓
@mengxi-ark/biz-components
    ↓
@mengxi-ark/components
    ↓
@mengxi-ark/hooks
    ↓
@mengxi-ark/theme
    ↓
@mengxi-ark/utils
```

> 约束：下层包绝对不能 import 上层包；biz-components 仅通过 `inject` 探测 runtime 上下文，不硬编码导入 runtime。

## 3. 各包详细职责、API规范、边界约束

### 3.1 `@mengxi-ark/utils`｜底层工具层（最稳定）

**职责**：纯无状态工具函数，无UI、无Vue依赖。

* 数据格式化：日期、金额、字典、数字
* 数据结构：树遍历、数组、对象合并、深拷贝
* 浏览器工具：下载、导出、blob、url参数
* 基础校验规则、编码、加解密辅助函数

**约束**

* 仅原生JS/TS，不依赖任何Vue生态包
* 全部纯函数，无全局状态、无副作用
* 兼容 Web、uniapp、Node 脚本导入
* 所有函数必须写类型，单元测试覆盖

**可维护规则**

* 废弃函数添加 `@deprecated` JSDoc，大版本才移除
* 单一文件单一分类，禁止大杂烩 utils.ts

### 3.2 `@mengxi-ark/theme`｜样式Token包

**职责**：设计规范载体，纯样式，无JS逻辑

* 全局CSS变量（Design Token：color、spacing、radius、shadow、z-index）
* 基础重置、排版、空状态、loading基础样式
* Antdv / Element Plus 变量覆盖脚本
* 亮色/暗色主题、主题覆盖入口

**约束**

* 不写硬编码色值，全部引用token
* 不包含Vue组件、业务逻辑
* 业务项目可外部覆盖变量，无需fork源码

### 3.3 `@mengxi-ark/hooks`｜通用逻辑钩子层（无工作台）

**职责**：中后台通用逻辑封装，不绑定Tab、工作台基座
分组：

* `useRequest`：请求、loading、错误、取消、重试、缓存
* `useAuth`：权限判断、v-permission 指令
* `useSession`：token、自动刷新、持久化、登出
* `useI18n`：国际化读取、切换
* `useTable`：查询、分页、排序、筛选状态
* `useForm`：表单回显、重置、校验封装

**约束**

* 仅依赖 Vue / Pinia / VueRouter
* 不导入 runtime；全局store支持手动传入降级
* 所有hooks支持配置覆盖，默认行为可关闭
* 不劫持路由原生API，路由守卫交给业务或runtime注册

### 3.4 `@mengxi-ark/components`｜通用增强组件层（可独立使用）

**职责**：基础UI增强组件，面向通用后台

* SearchForm 高级查询区、增强Table、TreeSelect、Upload、Dialog、Drawer
* 统一空状态、异常兜底、状态标签、Result结果页

**约束**

* 依赖 theme、hooks、底层UI适配器
* **完全独立可导入**，不需要基座注册
* 优先props驱动，插槽作为补充兜底
* UI差异收敛在适配器，上层组件尽量不改动

### 3.5 `@mengxi-ark/biz-components`｜业务语义组件（核心创新：双模式）

**职责**：B端单据类业务组件（对标HZERO Lov、单据表格、审批面板）
组件清单首期：Lov值集选择器、单据Table、审批进度面板、审计信息、版本对比、导入导出组件

**双模式规范**

1. **独立模式（默认降级）**：传入 `api、params、permission`，组件内部使用 `useRequest` 自行请求，不需要任何基座；uniapp X 蒸汽模式、H5弹窗都可以直接引入。
2. **基座联动模式**：`inject` 探测上层 runtime 上下文；探测成功自动复用全局值集缓存、用户信息、数据权限；**不import runtime**。

**约束**

* 所有基座提供的上下文字段，都支持props兜底
* 上下文丢失自动切独立模式，不抛出致命异常
* 组件只封装交互范式，不绑定后端固定字段

### 3.6 `@mengxi-ark/runtime`｜可选中台工作台基座（不强制）

> 只有做多模块中台、SaaS工作台才引入
> **职责**

* Tab工作台管理器：标签打开、缓存、关闭、打开策略（新Tab/弹窗/当前页）
* 全局上下文：user、tenant、org、全局值集缓存
* 模块注册中心 `registerModule`：注册路由、菜单、组件、权限项
* 全局路由守卫、会话监听、单点登出回调、全局异常拦截
* 内置工作台Layout（可替换，非强制）

**内部拆分Service**

* tabService、menuService、moduleRegistryService、sessionService、contextService
  **约束**
* 不修改Vue、Router底层原型，仅上层封装调度
* 提供生命周期钩子：`onAppInit`、`onBeforeRouteChange`、`onSessionExpired`，业务扩展走钩子，不fork源码

### 3.7 `@mengxi-ark/dsl-render`｜可选配置渲染引擎

**职责**：接收标准JSON Schema，渲染查询区、表单、表格

* 底层复用 components / biz-components
* 同样双模式：独立渲染 / 接入runtime自动读取值集、权限
* 支持自定义组件插槽、联动、显隐、校验

**约束**

* 手写SFC是一等公民，配置渲染只是加速方案
* Schema强TS类型，提供schema校验工具
* 渲染器只负责渲染，保存事件抛出给上层业务

### 3.8 `@mengxi-ark/cli`｜脚手架

**能力**

* `create-mengxi-ark` 初始化项目
  * 模板A：轻量模板（无runtime、无dsl）
  * 模板B：中台基座模板（runtime+模块注册）
* 代码生成器：根据接口生成表单、列表页面
* 版本对齐检查、组件模板生成

**约束**

* 模板尽量薄，业务能力全部通过npm包引入，不写死在模板内
* 模板必须内置面向使用者的精简 AI 规则（`.trae/rules/` 用法速查：安装、主题覆盖、双模式 props、按需导入）；轻量模板不得包含 runtime / 中台相关内容，规则随模板分档，使用者装完模板即获得规则
* 脚手架版本和框架包版本绑定，避免版本错乱

## 4. 开发规范、质量门禁、可维护性保障方案

### 4.1 代码规范

1. 统一 ESLint + Prettier，内部包 `internal/eslint-config` 统一收口
2. 命名规范：
   * 包：`@mengxi-ark/xxx`，短横线命名
   * 组件：PascalCase
   * hooks：useXxx 驼峰
3. 所有导出API必须写JSDoc注释，标注参数、返回值、可选基座联动说明
4. 禁止在底层包写业务硬编码、业务字典、业务接口地址

### 4.2 CI 质量门禁（GitHub Actions）

每次PR自动执行：

1. 依赖链路检查脚本：禁止反向import（biz-components import runtime 这类非法依赖直接阻断）
2. ESLint + 类型检查 `tsc --noEmit`
3. Vitest 单元测试
4. Turborepo build 全包构建校验
5. 包版本peerDependency对齐校验

> 不通过门禁，禁止合并到 master 分支

### 4.3 可维护性核心策略（落地化）

1. **变更频率隔离**
   * 低频稳定：utils / theme（谨慎发版）
   * 中频迭代：hooks / components / biz-components（持续新增组件）
   * 低频中台：runtime / dsl-render（严格控制破坏性变更）
2. **扩展优先，fork兜底**
   所有能力提供回调、适配器、插槽、生命周期钩子；业务优先使用扩展，只有通用能力才合并进框架内核。
3. **语义化版本 SemVer**
   * Patch：bug修复
   * Minor：新增组件、新增hooks、新增配置项（向下兼容）
   * Major：破坏性变更，必须附带迁移文档、迁移脚本
4. **Tree-Shaking 保障**
   * 全部输出ES Module
   * runtime、dsl-render 独立入口，不打包进基础组件包
   * biz-components 支持按需导入

## 5. 版本策略、发布流程、NPM包管理

1. 版本号统一管理：changesets 管理版本、生成changelog
2. 发布流程：
   1. 开发分支合并到 master，CI自动收集changeset
   2. 维护者执行 `pnpm changeset version` 统一 bump 版本
   3. 自动生成 `CHANGELOG.md`
   4. 执行 `pnpm publish` 发布到 npm，归属 `@mengxi-ark`
3. peerDependency 约束 Vue、Pinia、VueRouter 版本范围，避免多实例冲突
4. optionalDependencies 标记 runtime / dsl-render，不安装则不加载

## 6. 分支策略、Issue & PR 开源协作规范（CONTRIBUTING.md）

### 分支模型

* `master`：稳定发布分支，可随时打tag发布
* `feature/*`：新功能分支（组件、hooks、引擎能力）
* `fix/*`：bug修复分支
* `docs/*`：文档更新
* `release/*`：版本发布准备分支

### PR 规范

1. 一个PR只解决一个问题，禁止大杂烩PR
2. 标题格式：`[包名] 描述`，示例：`[biz-components] Lov组件增加独立模式params自动防抖`
3. 必须关联Issue，单元测试补齐
4. 至少一名维护者review通过，CI全部绿灯方可合并

### Issue 模板

* Bug Report
* Feature Request
* 文档反馈
* 讨论（Discussions 板块）

## 7. 文档体系规划（VitePress，部署 GitHub Pages）

文档分为三大板块，匹配渐进式使用场景：

1. **快速上手（轻量模式）【面向大多数使用者】**
   * 安装、起步、组件独立使用、hooks使用
   * 不提及 runtime、模块注册，降低心智负担
2. **中台进阶（Runtime 基座）【面向中台/SaaS开发者】**
   * 工作台Tab、模块注册、全局上下文、菜单权限、单点登录
3. **DSL配置渲染【低代码场景】**
   * Schema规范、组件映射、联动规则、自定义渲染
4. 附加：API文档、迁移指南、FAQ、最佳实践、从Vben/HZERO迁移对比

> 每个组件文档同时提供两套示例：独立模式示例、基座联动示例
